# Office Wallet — сброс пароля

Материалы стендового прогона показывают, что пароль тестовой учётной записи был изменён. Основная находка — [OW-26](../../SECURITY_PROGRESS.md#инвентаризация-дефектов-текущего-main). С ней связан [OW-27](../../SECURITY_PROGRESS.md#инвентаризация-дефектов-текущего-main), поскольку в исходном описании отмечен доступ сотрудника к общей почте с письмами о восстановлении.

## Что зафиксировано

| Материал | Наблюдение |
| --- | --- |
| Форма «Сброс пароля» | Приложение показало уведомление о запросе восстановления. |
| Форма «Новый пароль» | Интерфейс запрашивал номер заявки, SMS-код и новый пароль. |
| Журнал стендового прогона | Зафиксированы успешное обновление пароля и переход на страницу входа. |
| Кабинет Office Wallet | На снимке виден открытый кабинет с ролью сотрудника. Снимок сам по себе не устанавливает, когда была создана сессия. |
| Текстовое описание проверки | Автор описал избыточный доступ сотрудника к общей почте и отсутствие ограничения ошибочных вводов SMS-кода на проверявшемся стенде. |

Коммит стенда в приложенных материалах не указан. Результат относится к исходному прогону.

## Статус в main

Проверен код на коммите `3d2ffc5c4bb5dfa3670296c66a02fb2d45566086`.

| ID | Что подтверждено по коду | Что требует проверки |
| --- | --- | --- |
| OW-26 | Срок действия заявки составляет 15 минут. Заявка погашается в одной транзакции со сменой пароля. В обработчике нет лимита ошибочных вводов. | Проверить ограничения на стенде и закрыть оставшийся риск. |
| OW-27 | Просмотр общей почты ограничен администраторами. | Подтвердить, что приложение отклоняет запрос сотрудника на развёрнутом стенде. |

## Критерии проверки исправления

- Серия ошибочных вводов исчерпывает допустимое число попыток. Ограничение сохраняется при параллельных запросах и не обходится созданием новой заявки.
- Просроченная или уже использованная заявка отклоняется. При одновременной отправке двух корректных подтверждений обработчик принимает только одно.
- Сотрудник не может читать общую почту. У администратора сохраняется доступ в рамках его роли.

В этой проверке сверены исходные материалы и код `main`. Повторный прогон на стенде не проводился.
