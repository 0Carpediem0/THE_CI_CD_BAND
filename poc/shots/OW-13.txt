== 6. OW-13: чужие операции через токены /api/ops/feed ==
    · /api/ops/feed выдаёт подписи (op_grant) на 30 последних операций всех
    · пользователей и рассовывает их в cookie (handlers_money.go:97-127). А проверка
    · на /operations/N сверяет подпись только с uid того, кто смотрит (строки 78-89)
    · — то есть feed сам раздаёт валидные ключи от чужих операций.
    → SQL SELECT id FROM operations WHERE id >= (SELECT COALESCE(MAX(id)-29,0) FROM operations) AND COALESCE(from_user_id,0)<>1 AND COALESCE(to_user_id,0)<>1 ORDER BY id DESC LIMIT 1
    ← psql 648
    → SQL SELECT role FROM users WHERE login='ivanov'
    ← psql admin
    · у иванова роль admin (наши тесты переписали данные стенда) — админу и так
    · всё можно, проверка подписей его не касается; снимем роль, чтобы показать
    · проверку на себе. Важно: роль в куке перетирает роль из базы (auth.go:40-42),
    · поэтому после правки перелогиниваемся, чтобы кука тоже стала employee:
    → SQL UPDATE users SET role='employee' WHERE login='ivanov'
    ← psql UPDATE 1
    ← роль ivanov в базе: employee
    → POST /login  login=ivanov (куки → Client)
