Анализ безопасности «Office Wallet»

Корпоративный кошелёк (Go + PostgreSQL + Mailpit + notify-mock)
Команда: TUZteam · Дата: 26 ноября 2026
Объект: локальный стенд docker compose (http://localhost:18081), образ work-app:latest; боевой контур — *.devsecops-contest.ru
Режим: белый ящик (исходники + образ), подтверждение по сети приложения.

Все находки воспроизведены на чистом стенде (docker compose down -v && up). PoC лежат в poc/ и проходят 17/17 (artifacts/poc-run.txt). Для каждой находки приведены: суть, код с уязвимостью, класс OWASP/CWE, предусловия, шаги (curl + PoC), наблюдаемый результат, цепочки, критичность с CVSS 3.1 и рекомендация с патчем. Источник классов — OWASP Top-10 / CWE и hacksplaining.com.

Окружение и метод

Стенд собран из репозитория: docker compose up -d --build. Приложение (образ work-app, база debian:bookworm-slim) слушает :8080, опубликовано на 18081; PostgreSQL 16, Mailpit и notify-mock — отдельные сервисы. Учётки сида: ivanov/workplace1 (сотрудник), а также kassa (кассир), buch (бухгалтер), adminw (администратор).

PoC написаны под cookie-сессии приложения (новый клиент poc/wallet_client.py; прошлый KeptExpliots/_http.py рассчитан на Token-API другого стенда и не подходит). Прогон: docker run --rm --network work_default -v <poc>:/poc -w /poc python:3-alpine python run_all.py --base http://app:8080. Сканеры: Trivy 0.76.2 (образ + репозиторий), Nuclei 3.11.1 (стенд), заголовки — curl.

V-01. Ключи подписи захардкожены и утекают в клиентскую статику Critical · CVSS 9.8

A02:2021 / A05:2021 · CWE-798, CWE-321, CWE-547 · PoC: poc/01_key_leak_static_js.py

// app/static/wallet.js + legacy-sync.js -> "office-wallet" + "-session-key"

Шаги.

curl -s http://localhost:18081/static/wallet.js
curl -s http://localhost:18081/static/legacy-sync.js
# PAYMENT_KEY = office-wallet-pay-key ; SESSION_KEY = office-wallet-session-key
Результат. Оба ключа восстановлены и приняты сервером (подделанная admin-кука = 200). Все HMAC-механизмы (сессия, платёж, op-grant, supply-channel) скомпрометированы.
Цепочки. Корень: включает V-02, V-09, V-11, V-12. Даже с ротацией env-ключей статика продолжает раскрывать дефолты.
Фикс. Падать на старте при пустом/дефолтном/коротком ключе; удалить ключи из статики; op-grant и supply-channel не отдавать наружу. См. fixes/PATCHES.md (V-01).

V-04. SQL-инъекция в сумме перевода (error-based) Critical · CVSS 9.1

A03:2021 · CWE-89 · PoC: poc/04_sqli_transfer_errorbased.py
Суть. Если сумма не парсится как число, она подставляется в SQL строкой и исполняется; текст ошибки Postgres возвращается пользователю — классический error-based oracle.
Расположение.

if qerr != nil { msg = qerr.Error() + " | " + q }   // утечка ошибки + запроса
Предусловия. Любая сессия (подойдёт ivanov/workplace1).
Шаги.

 -d "recipient=ivanov&memo=x" http://localhost:18081/transfer/new
Результат. Слиты логины и bcrypt-хэши всех пользователей (и version()). Через приведение текста к bigint Postgres возвращает значение в сообщении об ошибке.
Цепочки. Хэши → офлайн-подбор; lib/pq в simple-query режиме допускает и stacked-запросы (модификация данных).
Фикс. Парсить сумму в Go, не класть в SQL; общий текст ошибки (V-04/V-24 в PATCHES).
