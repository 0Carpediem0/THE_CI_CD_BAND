Анализ безопасности «Office Wallet»

Корпоративный кошелёк (Go + PostgreSQL + Mailpit + notify-mock)
Команда: TUZteam · Дата: 26 ноября 2026
Объект: локальный стенд docker compose (http://localhost:18081), образ work-app:latest; боевой контур — *.devsecops-contest.ru
Режим: белый ящик (исходники + образ), подтверждение по сети приложения.

Отчёт — объединение двух копий репозитория. Карточки V-01…V-28 — прогон poc/kept/ (17/17, artifacts/poc-run.txt). Карточки V-29…V-40 — цепочки из poc/ (stage_access.py, stage_money.py, stage_data.py, stage_xss.py, stage_registry_extra.py), которых в первом отчёте не было. Реестр OW-01…OW-44 сведён с V-карточками в таблице ниже. Для каждой находки приведены суть, код, класс OWASP/CWE, предусловия, шаг воспроизведения, результат, цепочка и рекомендация. Источник классов — OWASP Top-10 / CWE и hacksplaining.com.

Окружение и метод

Стенд собран из репозитория: docker compose up -d --build. Приложение (образ work-app, база debian:bookworm-slim) слушает :8080, опубликовано на 18081; PostgreSQL 16, Mailpit и notify-mock — отдельные сервисы. Учётки сида: ivanov/workplace1 (сотрудник), а также kassa (кассир), buch (бухгалтер), adminw (администратор).

PoC написаны под cookie-сессии приложения (новый клиент poc/kept/wallet_client.py; прошлый KeptExpliots/_http.py рассчитан на Token-API другого стенда и не подходит). Прогон: docker run --rm --network work_default -v <poc>:/poc -w /poc python:3-alpine python run_all.py --base http://app:8080. Сканеры: Trivy 0.76.2 (образ + репозиторий), Nuclei 3.11.1 (стенд), заголовки — curl.

Что в карту не входит

Ниже звенья из первого текста отчёта и из CHAINS.md / poc/. На текущем коде стрелка не проводится.

  • V-01 → V-02 → V-08. Статика собирает строку office-wallet-session-key, а server.go с таким ключом не стартует. currentUser после проверки подписи загружает пользователя из БД и поле роли в куке не применяет. /gateway/sms открыт только IsAdmin(). Письмо сброса код не содержит.
  • V-02 → V-05 / V-03 → V-19. Сверка параметризована, превью чека экранируется. exec.Command запускает фиксированное uname -a, не строку атакующего. В main эта стрелка была записана как RCE через уведомления.
  • V-01 → V-09 и V-04 → хэши. Подпись повтора уже стоит в истории самого пользователя (ReplaySig). Сумма перевода разбирается parseRubToKop, в SQL не подставляется.
  • XSS → кража ow_session → эскалация. У ow_session стоит HttpOnly: true. Без HttpOnly остаётся только op_grant_*. Эскалации роли это не даёт.
  • V-29 → V-07. Добавлено из poc/stage_money.py. У заказа за 0 total_kop = 0, возврат 0 × qty денег не печатает.
  • V-18 → V-37 → V-38 и V-36 → V-08 → V-23 → V-33/V-39. Добавлено по мотивам main/CHAINS.md. Запись в базу уже полный доступ, обход blocked ей не нужен. Брут логина не ведёт к сбросу пароля. Кука SameSite=Lax, чужой сайт POST-запросом чаевые и op_type не отправит. V-39 меняет только вид проводки.
  • Из poc/ отдельно: отмена чужого заказа (владелец проверяется), общий ящик почты (только admin), переполнение рублей в копейки (ParseInt возвращает ошибку), двойное подтверждение перевода (черновик снимается в транзакции).

V-04. SQL-инъекция в сумме перевода (error-based) Critical · CVSS 9.1

A03:2021 · CWE-89 · PoC: poc/kept/04_sqli_transfer_errorbased.py
Суть. Если сумма не парсится как число, она подставляется в SQL строкой и исполняется; текст ошибки Postgres возвращается пользователю — классический error-based oracle.
Расположение. 
// app/internal/app/handlers_money.go — transferNew()
q := fmt.Sprintf("SELECT %s::bigint", amountStr)
_, qerr := s.db.Exec(q)
if qerr != nil { msg = qerr.Error() + " | " + q }   // утечка ошибки + запроса
Предусловия. Любая сессия (подойдёт ivanov/workplace1).
Шаги. 
# логинимся, сохраняем куку, затем:
curl -s -b cj.txt --data-urlencode \
 "amount_rub=(SELECT string_agg(login||':'||password_hash,'; ') FROM users)" \
 -d "recipient=ivanov&memo=x" http://localhost:18081/transfer/new
Результат. Слиты логины и bcrypt-хэши всех пользователей (и version()). Через приведение текста к bigint Postgres возвращает значение в сообщении об ошибке.
Цепочки. В текущем transferNew сумма проходит через parseRubToKop и в текст SQL не попадает. Выгрузка хэшей этой стрелкой не подтверждается.
Фикс. Парсить сумму в Go, не класть в SQL; общий текст ошибки (V-04/V-24 в PATCHES).
